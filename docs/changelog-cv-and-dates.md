# Резюме и даты в биографии

Ветка `cv-and-bio-dates`, два коммита поверх `master`. Один чинит хронологию
на сайте, второй переносит резюме в репозиторий и переводит на него кнопку CV.

```bash
git switch master              # было
git switch cv-and-bio-dates    # стало
git diff master --stat         # весь объём правки
```

## 1. Биография на сайте

Даты в `experience` были неверны в трёх местах, и одного места работы не было
вовсе. Заменено на версию из резюме Ганны, подтверждённую ею 17.09.2026.

| Компания | Было | Стало |
| --- | --- | --- |
| Laboratory 24 LLC | Oct 2015 — Feb 2016 | *без изменений* |
| R-Soft LLC | Oct 2016 — Feb 2017 | *без изменений* |
| SprintSoft LLC | **Oct 2016 — Feb 2017** | **Feb 2017 — Jun 2019** |
| GMCS Verex LLC | **Feb 2017 — Feb 2021** | **Jun 2019 — Aug 2022** |
| Consolware GmbH, Berlin | **отсутствовал** | **Aug 2022 — Jan 2026** |
| Freelance | **Feb 2021 — Present** | **Feb 2026 — Present** |

У SprintSoft стояли даты R-Soft — два места работы делили один период, а
пять лет между 2017 и 2022 были записаны на GMCS. Заодно уточнены три
должности: у Laboratory 24 и SprintSoft показаны повышения
(`2D Designer → Head of 2D Design`, `UI/UX Designer → Senior UI/UX Designer`),
фриланс стал `Senior UX/UI Designer` вместо `Lead UI/UX Designer`.

**Смотреть:** [`src/data/about.ts:16`](../src/data/about.ts#L16) — весь массив
`experience`. Страница `/about` рисует его как есть, строка из шести карточек
вместо пяти.

**Что проверено и не потребовало правки:** в `clients.ts` дат нет вообще, а все
`period` в `projects.ts` — это сроки проектов, а не работы, и ни один не
противоречит новой хронологии.

## 2. Резюме: из Pages в репозиторий

Резюме было документом Pages вне репозитория — поэтому его дефекты и жили так
долго. Теперь это `cv/cv.html`, из которого headless Chrome собирает PDF.

```bash
npm run cv
```

Четыре дефекта, ради которых всё затевалось:

| Было | Стало |
| --- | --- |
| Адрес портфолио напечатан как `eobuddha` | `kreobuddha.github.io/ganna-portfolio`, и это настоящая ссылка |
| Ссылки — просто текст | Четыре кликабельных аннотации в PDF |
| Дата рождения на первой странице | Нет ни даты рождения, ни фотографии |
| Пять страниц | Две |

**Смотреть:**

| Файл | Что там |
| --- | --- |
| [`cv/cv.html`](../cv/cv.html) | Вся вёрстка: `@page` и типографика в `<style>`, контент ниже |
| [`cv/cv.html:262`](../cv/cv.html#L262) | Четыре контакта — почта, Telegram, LinkedIn, портфолио |
| [`cv/README.md`](../cv/README.md) | Как собирать и чего держаться при правках |
| `cv/Hanna_Shyliaieva_Senior_UX_UI_Designer.pdf` | Собранный файл, имя ровно такое, каким уходит |
| [`package.json:14`](../package.json#L14) | Команда сборки |

### Одно место, которое стоит посмотреть отдельно

[`cv/cv.html:95`](../cv/cv.html#L95) — маркеры списков. Chrome пишет текст в
PDF **в порядке отрисовки**, а не разметки, а позиционированный блок рисуется
после всего потока. Пока маркеры были `position: absolute`, все буллеты
вываливались из файла *после* остального содержимого страницы: обязанности
отрывались от компаний, к которым относятся. Разница видна не глазами — только
если скопировать текст из PDF или прочитать его парсером, то есть ровно так,
как его читает ATS. Сейчас маркеры — `::before` в потоке.

Отсюда же требования, которые нельзя ронять при правках: одна колонка, ничего
под текстом, серый не мельче 10pt. Они все про одно и то же — про то, что
резюме читает не только человек.

## 3. Кнопка CV на сайте

Вела на старый файл в Google Drive — тот самый, с опечаткой, датой рождения и
пятью страницами. Теперь отдаётся с самого сайта.

| Файл | Что изменилось |
| --- | --- |
| [`src/data/profile.ts:21`](../src/data/profile.ts#L21) | Ссылка на Drive → `documents/Hanna_Shyliaieva_Senior_UX_UI_Designer.pdf` |
| [`src/components/ContactPills/ContactPills.tsx:43`](../src/components/ContactPills/ContactPills.tsx#L43) | `resolveHref` — относительный href получает базовый путь сайта |
| [`package.json:15`](../package.json#L15) | `postcv` копирует PDF в `public/documents/` |

Копия в `public/documents/` заполняется сборкой, а не руками, — разойтись с
`cv/` она не может. В гит она попадает потому, что на деплое нет Chrome, чтобы
собрать её заново.

Относительный путь важен: сайт живёт под `/ganna-portfolio/` на GitHub Pages,
и абсолютный `/documents/...` там бы не нашёлся. Та же логика, что у писем
рекомендаций в [`public-documents.md`](public-documents.md).

## Осталось

- **Удалить старое резюме с Google Drive.** Ссылка на него разослана в
  переписках и ведёт на версию с опечаткой; сайт на неё больше не смотрит, а
  переписки смотрят.
- **Behance.** В требованиях он был среди ссылок, но адреса нет ни в контенте,
  ни в репозитории. Выдуманный URL на резюме хуже отсутствующего — добавить
  можно одной строкой, когда адрес найдётся.
- **LoveBerry.** В [`projects.ts`](../src/data/projects.ts) проект 2021 года
  описан как `freelance commission`, а по исправленной хронологии в 2021 она
  была в GMCS. В резюме LoveBerry — единственный проект без пометки «via …»,
  так что это читается как подработка на стороне и противоречия нет. Но если
  это не так, строку надо поправить.
